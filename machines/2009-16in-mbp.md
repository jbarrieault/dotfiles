# 2009 16in MBP — Omarchy

Machine-specific setup notes for the Omarchy (Arch + Hyprland) install on this
box. `install.sh` is macOS/Homebrew-focused and doesn't apply here — everything
below was done by hand (or symlinked) instead.

## Dotfiles applied

This repo's top-level configs (`nvim/`, `tmux/`, `ghostty/`, `herdr/`,
`starship.toml`) are the macOS/Homebrew setup that `install.sh` targets.
Omarchy machines diverge from that in ways worth keeping separate (see
"Omarchy divergence" below), so this box symlinks from **`omarchy/`** instead —
a copy of those same configs, seeded from the mac ones and then adjusted per
app as needed:

```
ln -s ~/dotfiles/omarchy/nvim ~/.config/nvim
ln -s ~/dotfiles/omarchy/tmux ~/.config/tmux
mkdir -p ~/.config/ghostty && ln -s ~/dotfiles/omarchy/ghostty/config ~/.config/ghostty/config
mkdir -p ~/.config/herdr && ln -s ~/dotfiles/omarchy/herdr/config.toml ~/.config/herdr/config.toml
ln -s ~/dotfiles/omarchy/starship.toml ~/.config/starship.toml
```

(Omarchy already ships its own default configs at these same paths — the
existing versions were backed up locally to
`~/.config/dotfiles-backup-<timestamp>/` before being replaced, not committed
here.)

**Trade-off:** Omarchy's own versions of the nvim/tmux/ghostty configs include
integrations neither the mac nor the `omarchy/` configs have (yet): automatic
light/dark theme sync for nvim, a tmux keybindings help popup, and a couple of
nvim QoL tweaks (disabled news alert, animated scrolling off). Symlinking
replaced all of that. If any of it is worth having back, port it into
`omarchy/` rather than re-linking to Omarchy's defaults.

### Omarchy divergence

Changes made only in `omarchy/`, not in the mac configs at the repo root:

- **`omarchy/ghostty/config`** — dropped the static `theme = ...` line and
  added `config-file = ?"~/.local/state/omarchy/current/theme/ghostty.conf"`
  instead, so Ghostty always follows whatever Omarchy theme is active
  (`omarchy theme set ...`) rather than a fixed theme. Foot (this machine's
  original default terminal) uses the same mechanism via its own
  `~/.local/state/omarchy/current/theme/foot.ini`, which is why the two used
  to look alike.
- Font size in `omarchy/ghostty/config` needs tuning down from the mac
  default of 18 — TODO once a concrete value is picked.

### tmux plugins

`omarchy/tmux/tmux.conf` (inherited from the mac config) expects TPM at the
old macOS-style path (`~/.tmux/plugins/tpm`, not XDG
`~/.config/tmux/plugins`). Cloned manually rather than editing the conf:

```
git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm
git clone https://github.com/tmux-plugins/tmux-sensible ~/.tmux/plugins/tmux-sensible
git clone https://github.com/tmux-plugins/tmux-resurrect ~/.tmux/plugins/tmux-resurrect
```

### nvim

Ran a headless `Lazy sync` after symlinking to pull in this repo's plugin set
(claudecode.nvim, neotest, etc.) — bumped `omarchy/nvim/lazy-lock.json`.

## Omarchy/Hyprland config changes

All in `~/.config/hypr/input.lua` (Omarchy loads its defaults first, then this
file — only uncommented keys override):

```lua
hl.config({
  input = {
    -- Remap Caps Lock to Escape (system-wide, XKB-level; all contexts).
    kb_options = "caps:escape",

    touchpad = {
      -- Invert the default (Omarchy ships natural_scroll = false).
      natural_scroll = true,
    },
  },
})
```

## System config changes (outside `~/.config`, not symlink-managed)

`/etc/systemd/logind.conf.d/30-ignore-lid-switch.conf` — added as a new
drop-in (existing drop-ins in that directory are owned by the `omarchy-settings`
package, so this avoids editing package-managed files directly):

```ini
# Laptop lid closed with an external display/dock attached should not
# suspend or lock this machine — it stays running as a headless/docked box.
[Login]
HandleLidSwitch=ignore
HandleLidSwitchExternalPower=ignore
HandleLidSwitchDocked=ignore
```

Takes effect on next boot/login. **Do not** apply it with a live
`systemctl restart systemd-logind` — doing so while a graphical session is
active desyncs VT/seat ownership from the running compositor and can crash
the session hard enough to need a power-cycle (learned this the hard way on
2026-09-12).
